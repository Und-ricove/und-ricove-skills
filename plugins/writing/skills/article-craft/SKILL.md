# article-craft — как строить статьи и артефакты

Скилл собран 04.08.2026 из опыта четырёх опубликованных артефактов, главный урок —
из статьи «Мыло на OLED». Цель: **не проектировать оформление заново каждый раз.**
Ниже готовые решения. Отступать от них можно, но осознанно и с причиной.

---

## Эргономика пользователя — это жёсткие требования, не вкусовщина

- **Тонкий текст физически утомляет до головокружения.** Ниже 400 веса не опускаться
  нигде, включая подписи и сноски. В интерфейсах — Segoe UI Semibold.
- **Базовый кегль 17–18 px, интерлиньяж 1.7.** Не 15, не 16. Строка 60–70 знаков.
- **Плотные таблицы и мелкий кегль запрещены** — отчёт должен читаться, а не
  разбираться. Если данные не влезают крупно, значит их надо разбить или сократить.
- Плотность контента ограничена сверху: лучше три коротких раздела, чем один плотный.

---

## Шрифты — главный урок статьи про мыло

**Что было сделано неправильно.** В артефакте «Мыло на OLED» тело статьи набрано
**JetBrains Mono, инлайненным data-URI**. Три последствия:

1. **Лигатуры в тексте.** JBM склеивает `->`, `>=`, `!=` в глифы. В коде это помощь,
   в связном тексте — спотыкание. Такой шрифт годится для поэзии и коротких форм,
   где каждая строка рассматривается отдельно, но не для лонгрида.
2. **Моноширинность.** Равная ширина знаков замедляет чтение длинного текста: глаз
   теряет опору на силуэт слова.
3. **Вес 423 КБ**, из которых почти всё — base64 шрифта. Страница грузится
   несоразмерно своему содержанию.

**Лигатуры запрещены везде — решение пользователя 04.08.2026.**

Проверено поиском по литературе: **исследований, подтверждающих пользу программистских
лигатур, найти не удалось.** Работ по eye-tracking в чтении кода много (размер, сложность,
комментарии), по лигатурам — ни одной. Статей «в защиту лигатур» много, доказательств нет,
а количество публикаций истине не равно.

Рассуждение пользователя, которое принимается за рабочее: **и слабое, и хорошее зрение
одинаково тратят усилие на вопрос «это один знак или два склеенных».** Пока обратное
не доказано — не применять. Отсутствие доказательств вреда доказательством
безопасности не является.

**Стек по умолчанию:**

```css
/* тело статьи — Verdana: широкие пробелы, крупный x-height, лигатур нет */
font-family: 'Verdana Pro', Verdana, 'DejaVu Sans', Geneva, sans-serif;
/* заголовки — тот же род, плотнее и с отрицательным трекингом */
font-family: 'Verdana Pro', Verdana, 'Segoe UI', sans-serif;
/* числа, код, формулы — ТОЛЬКО здесь, версии без лигатур */
font-family: 'JetBrains Mono NL', 'Cascadia Mono', Consolas, 'DejaVu Sans Mono', monospace;
```

⚠️ **Различать по имени:** `Cascadia Mono` — без лигатур, `Cascadia Code` — с ними.
`JetBrains Mono NL` (No Ligatures) — без, обычный `JetBrains Mono` — с. В стеке
указывать только безлигатурные варианты; страховкой стоит `Consolas`, где их нет вовсе.

Проверено на Windows 11: **Verdana установлена** (`verdana.ttf` + жирный,
курсив, чёрный), Verdana Pro и JetBrains Mono — нет. Поэтому Pro стоит первым как
улучшение, а не как требование.

Дополнительная страховка на случай гарнитуры с лигатурами у зрителя:

```css
body { font-variant-ligatures: none; }
pre, code { font-variant-ligatures: none; font-feature-settings: "liga" 0, "calt" 0; }
```

**Никогда не подключать шрифт по URL** — CSP артефактов блокирует внешние хосты,
и подмена произойдёт молча.

## Скелет, от которого начинать

Токены на `:root`, переопределение в трёх местах — иначе тема ломается в одну сторону.

```css
:root { --ground:…; --panel:…; --ink:…; --muted:…; --rule:…; --accent:…; }
@media (prefers-color-scheme: dark) { :root { …только токены… } }
:root[data-theme="dark"]  { …те же токены… }
:root[data-theme="light"] { …те же токены… }
```

Компоненты стилизуются **через токены**, никогда внутри медиазапроса.

Прочее по умолчанию:

- сетка — `flex`/`grid` + `gap`, не поля у соседей;
- широкое (таблицы, код, схемы) — в своём контейнере с `overflow-x: auto`;
- колонки цифр — `font-variant-numeric: tabular-nums`;
- фокус клавиатуры виден всегда; `prefers-reduced-motion` уважается;
- в артефактах базовый `body` приходит тёплым кремовым (#faf9f5) — перекрывать явно,
  иначе получится непрошеный «AI-бежевый».

## Палитра — брать готовую из `palette.md`

Рядом со скиллом лежит **[palette.md](palette.md): 42 сочетания, посчитанных по WCAG**
(24 основных + 12 глубоких + 6 состояний). Контраст текст/блок везде **≥ 10:1**.

### 🔴 Главное правило: текст — на вершине, противоположной фону

Две редакции палитры были отозваны, прежде чем правило нашлось. Обе ошибки полезно
знать, потому что обе выглядят разумно.

**Ошибка 1: один оттенок на все три роли.** Контраст проходил AAA, но зрение читало
текст, блок и фон как родственные поверхности — текст тонул в своей палитре.

**Ошибка 2: текст сделали почти нейтральным.** Помогло частично. Причина провала:
**нейтральный — не значит противоположный.** Слабый уклон текста оставался в той же
половине круга, и хроматический контекст по-прежнему был общим.

**Ошибка 3: текст в противоположном оттенке (180° от фона).** Слияние исчезло, но
появилось раздражение: тёмный слабонасыщенный тёплый цвет читается как **«коричневый,
но не явно коричневый»**. У него нет категории — зрение не может отнести его ни к серому,
ни к коричневому и снова и снова возвращается, пытаясь назвать.

**Действующее правило: у текста нет оттенка вообще.**

```
хроматика текста = 0.000  (LAB a = 0, b = 0)
хроматика фона   = 0.08–0.10
```

Это снимает обе проблемы разом:

- **Слияния нет:** нейтраль не принадлежит ни одной цветовой семье, и хроматической
  адаптации нечего вычитать. Ошибка Р1–Р2 была не в нейтральности текста, а в том, что
  он был **слабо окрашен в тот же оттенок**. Ноль и «почти ноль» ведут себя по-разному.
- **Классификации не требуется:** серый — базовая категория, опознаётся мгновенно.
  Любой слабый уклон создаёт цвет без имени, и мозг к нему возвращается.

**Цена нулевая:** хроматические каналы имеют низкое пространственное разрешение, буква
распознаётся практически только по яркости — цвет в тексте не работал в любом случае.

### Порядок приоритетов при выборе — жёсткий

1. **Цвет шрифта.** Светлый текст на тёмном — **самое опасное сочетание**, белое
   на чёрном худшее из них: **halation** заставляет светлые буквы расплываться
   в темноту, особенно при астигматизме; при дислексии предельный контраст тоже
   читается тяжелее. Текст **всегда тёмный на светлом и почти нейтральный.**
2. **Блок под текстом.** Ограничивает зону чтения и снимает вопрос «где кончается
   строка». Светлее фона, но **не белый**: #FFF против #000 — 100 % против 0 %
   яркости, перегрузка на длинном чтении.
3. **Фон подстраивается последним** и забирает себе весь цвет.

### Пустой фон и сетка

Большое незанятое поле мозг пытается расшифровать: ищет структуру, не находит,
тратит ресурс. Тот же эффект, что от чистого белого листа. Лечится **сеткой**.

**Сетка строится белым, а не тёмным.** Примесь **белого** к фону — 35 % в основном
ряду, 38 % в глубоком. Тёмная линия попадает в тот же диапазон, что и строки текста,
и глаз вынужден различать «буква или разметка»; белая уходит в сторону света
и с текстом по природе не конкурирует.

**Заметная сетка — симптом, а не причина.** Она бросается в глаза тогда, когда текст
не противопоставлен фону по оттенку. Порядок починки: сначала проверить угол между
оттенками, потом плотность линии. Правило: сетку **не должно быть видно** при взгляде
на текст, только при взгляде на пустое место.

Нейтраль выбирается, а не наследуется. Один акцент, остальное тихо. Акцентом
**не набирают текст** — только линии, рамки и метки. Семантика состояния — отдельно
от акцента темы.

## Чего не делать: признаки «сгенерированного» оформления

Кремовый фон + серифный дисплей + терракота · near-black с кислотным пятном ·
градиент из фиолетового в синий · Inter и Space Grotesk как «безопасный выбор» ·
эмодзи вместо маркеров разделов · всё по центру · скруглённые карточки с акцентной
полоской слева · нумерация 01/02/03 там, где нет настоящей последовательности.

**Структурные элементы обязаны нести правду.** Нумерация — только если это
действительно очерёдность. Идентификаторы (Д-1, R-C2, p27) — можно всегда: они
адресуют, а не украшают.

## Структура подачи — что сработало в статье про мыло

Порядок разделов там оказался сильнее оформления, его и переносить:

1. **Разделить смешиваемые явления.** «Словом „мыло" называют минимум два несвязанных
   явления. Пока они не разделены, лечение бьёт мимо» — статья начинается не с решения,
   а с разграничения. Это снимает 80 % путаницы читателя.
2. **Дать разделительный вопрос.** Один вопрос, разрубающий дерево версий пополам:
   «есть мыло в файле или нет». Читатель ставит себя в ветку сам.
3. **Механизм важнее реализации.** При переносе статьи в заметку интерактивные стенды
   заменили текстовым описанием — и статья не пострадала. Значит несущее в ней было
   объяснение, а не витрина. Проверяйте себя этим: если убрать всю графику,
   останется ли смысл.
4. **Вычеркнутое хранить наравне с найденным.** Раздел «версии, которые не подтвердились»
   экономит следующему заходу больше, чем список решений.

Для инженерных записок работает жёсткая рамка на каждый пункт:
**симптом → механизм → цена → обход.**

**Приём для материалов о неверных данных:** визуальная пара «заявлено / проверено» —
ложное приглушённым с зачёркиванием, верное акцентом. Читается без чтения.

## Русский язык — гуманность к читателю

**Правило пользователя, 04.08.2026.** Русский путает даже носителей. Формально
корректная конструкция может быть тяжёлой — и грамотный носитель её избегает,
потому что заботится о том, кто будет читать.

**Избегать двойных отрицаний и связок «ни…ни» там, где можно перестроить фразу.**

Пример, который вызвал правило:

> ❌ «Ни что результат относится к этой формуле, ни что подставлены те же входные
> данные, она не гарантирует.»

Формально ошибки нет. Но конструкция `ни что… ни что… не` заставляет читателя
разбирать предложение, а не понимать его. Перестроенный вариант:

> ✅ «Она не подтверждает ни привязку результата к этой формуле, ни совпадение
> входных данных.»

Ещё лучше — уйти от отрицания вовсе:

> ✅ «Она говорит лишь о том, что инструмент вызывали. Формула и входные данные
> остаются непроверенными.»

**Метод — метаморфоз грамматики.** Язык позволяет менять слова и их порядок:

- заменить отрицание синонимом-утверждением (`не гарантирует` → `оставляет открытым`);
- разбить на два коротких предложения вместо одного с двойным отрицанием;
- чередовать синоним и антоним, чтобы уйти от тавтологии `не+не` / `ни+ни`;
- вынести отрицание в одно место фразы, а не рассыпать по ней.

**Ориентир — поэтическая традиция.** Эталон, названный пользователем, — песенная лирика
Анатолия Поперечного («Трава у дома», музыка Владимира Мигули). Текст целиком здесь
не приводится: он охраняется авторским правом. Ценность для нас не в словах, а в приёмах,
и они переносятся без цитирования.

Что там работает и что стоит перенимать:

- **Инверсия определения** («путями неизбитыми» вместо «неизбитыми путями») — акцент
  переезжает на признак, строка получает опору в конце, а не в начале.
- **Творительный падеж как инструмент образа** («прошит метеоритами») — метафора
  строится грамматикой, без служебных «как» и «словно». Для технического текста это
  прямой способ убрать сравнительные костыли.
- **Причастие вместо глагола** — состояние вместо действия. Описание перестаёт
  суетиться.
- **Ноль отрицаний.** Образ построен утверждением целиком — то самое, к чему сводится
  правило выше.
- **Плотность без спотыкания:** четыре слова несут пространство, движение и опасность
  одновременно, и ни одно не требует перечитывания.

Оценка носителей, которую приводит пользователь: это «утраченная способность использовать
русский язык так ярко, богато и элегантно, что слушание вызывает тягу вернуться
к истокам». Ориентир именно на это ощущение — не на украшательство, а на **плотность,
которая не мешает**.

**Что проверять перед сдачей:** двойные отрицания · `ни…ни` длиннее одной строки ·
канцелярские цепочки родительных падежей («проверки корректности значения параметра») ·
пассив там, где есть действующее лицо.

## Блок происхождения — обязателен (канон К1)

Любая статья, сводка и отчёт заканчиваются блоком: чем считали, каким методом,
какая модель, дата. Документ обязан доказывать своё происхождение сам, не отсылая
к соседней заметке.

Атрибуцию модели брать из **системного идентификатора**, а не из того, как к тебе
обратились в диалоге. При расхождении — доверять системному и сообщать о конфликте.

---

## Числа в статье — отдельная дисциплина

Оформление не спасает неверное число, а хорошее оформление делает его **убедительнее**,
и потому опаснее. Перед сдачей любого текста с числами применять скилл
`number-forensics` целиком. Минимум для статьи:

- **у каждого числа в тексте указано, что оно измеряет** («16 п.п. падения КПД между
  ε=0.30 и ε=0.50», а не «16 п.п.»);
- **числа пересчитаны на месте**, а не перенесены из источника, даже если рядом
  с ними в источнике стоит метка инструмента;
- **слишком точное совпадение** («−0.11 %» при разбросе входных данных в десятки
  процентов) в тексте не подаётся как сила аргумента — это признак подгонки;
- если одно и то же значение приводится в нескольких местах статьи, **все вхождения
  сверяются между собой** перед публикацией.

## OPSEC для публикуемого

Конфиденциально всё, что вокруг кукол, включая среду обитания. Инструменты разработки —
нет. Перед публикацией вычистить: имена детей, названия проектов и компании,
абсолютные пути с именем учётной записи, упоминания Матрикса и внутренних систем.
Технику оставлять, идентичность убирать.

**Публиковать артефактом только по прямому слову пользователя.** Локальный файл —
источник истины; артефакт — производная витрина. Пополнять сначала файл, затем
переопубликовать по тому же пути (URL сохранится).

## Порядок работы

1. Прочитать задачу и решить: утилитарная записка или витрина. Большинство — записки.
2. Набросать план: 4–6 цветов, три роли шрифта, одна фраза про сетку.
3. Проверить план на признаки шаблонности из списка выше. Что совпало — переделать.
4. Написать, применяя скелет.
5. Вычитать по чек-листу русского языка.
6. Добавить блок происхождения.

## Печать: HTML → PDF без установки чего-либо (урок 06.09.2026)

Edge headless есть на каждой Windows-машине:
```
msedge.exe --headless=new --disable-gpu --no-pdf-header-footer --print-to-pdf="out.pdf" "file:///C:/path/doc.html"
```
Экранная версия статьи в печать не годится: серый фон с сеткой съедает тонер и читается хуже. Для печатной версии
добавить в `<head>` перекрывающий блок: `@page{size:A4;margin:14–16mm}`, `body{background:#fff;font-size:12–13pt;line-height:1.35–1.5}`,
сетку убрать, `.sheet{border:1px solid #999}`, у больших блоков `page-break-inside:avoid` только там, где блок короче
страницы (иначе пустые хвосты). Переписки печатать без двойных `<br>` и 11pt — 36 сообщений влезают в 7 страниц вместо 15.
Проверка: pypdf считает страницы (`uv run --with pypdf`), снимок вёрстки — тем же Edge с `--screenshot` и `--window-size=1000,2300`;
`Read` PDF на этой машине не работает (нет pdftoppm), смотреть PNG.
Чувствительные документы (мед., паспорт) класть в `%USERPROFILE%\medical-private\`, на рабочий стол — только копию
для выдачи и убирать её в Корзину после события (правило уборки стола).
