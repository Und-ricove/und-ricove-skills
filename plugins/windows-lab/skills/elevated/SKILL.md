# Elevated-операции: UAC-паттерн

Как безопасно делать системные правки, требующие прав администратора, из обычной (неповышенной) сессии. Паттерн выработан опытом — отступления от него уже приводили к тихим ложным успехам.

## Зачем именно так

- Правки реестра/системы из песочницы могут **ТИХО виртуализоваться**: запись уходит в копию, `Get-ItemProperty` из той же сессии показывает «успех», а реальная система не изменилась. Критичные правки — только elevated.
- CIM/WMI без прав может тихо вернуть пусто/0. `Get-MpPreference` (Defender) без прав отдаёт N/A — **исключения Defender смотреть можно только elevated**.
- Инлайн-команды через `-Command` с экранированием ломаются на кавычках и кириллице. **Только `-File` со скриптом на диске.**

## Схема (шесть шагов, порядок обязателен)

1. **Скрипт-файл** в `%USERPROFILE%\.claude\scripts\<тема>\<имя>.ps1`, UTF-8 без BOM. Скрипт самодостаточен: сам делает правку, сам себя верифицирует, сам пишет итог.
2. Скрипт **пишет результат в файл**, а не только на экран (окно закроется — следов не останется):
   ```powershell
   $out = Join-Path $env:TEMP '<имя>-result.txt'
   $log | Set-Content -Path $out -Encoding utf8
   ```
3. Перед запуском **удалить старый файл-результат** (иначе можно прочитать прошлогодний успех): `Remove-Item $out -ErrorAction SilentlyContinue`.
4. **ПРЕДУПРЕДИТЬ пользователя**: сейчас появится окно UAC на защищённом столе (экран притемнится, нужно нажать «Да»). Без предупреждения — не запускать.
5. Запуск и ожидание:
   ```powershell
   Start-Process pwsh.exe -Verb RunAs -Wait -ArgumentList '-NoProfile','-ExecutionPolicy','Bypass','-File',$script
   ```
6. Неповышенная сессия **читает файл-результат**. Файла нет → UAC отклонён или пропущен. **НЕ повторять молча** — сказать пользователю и спросить, пробуем ли ещё раз.

## Верификация — двухканальная

- **Внутри elevated-скрипта** (тот же канал, что и правка): `reg query` / `Get-ItemProperty` / `Get-MpPreference` сразу после изменения, результат — в тот же файл. Правка без верификации в логе не считается сделанной.
- **Дублирующая проверка из обычной сессии**, где возможна: чтение реестра (`reg query`) работает без прав; Defender — нет, там верим только elevated-каналу.

## Требования к скрипту

- `$ErrorActionPreference = 'Continue'` + `try/catch` на каждый шаг; ошибки — в `$log` строкой «ОШИБКА: …», а не молчаливое падение. Пакет из нескольких правок должен доехать до конца и отчитаться по каждой.
- Формат лога: «БЫЛО → ДЕЛАЮ → СТАЛО» — состояние до, действие, состояние после (пример — мини-шаблон ниже).
- Пути — через `$env:USERPROFILE` / `$env:TEMP`, без хардкода имени учётки (OPSEC).
- В шапке скрипта — комментарий: что делает, зачем, **как откатить**.
- `Write-Host` дублировать можно (живое окно полезно пользователю), но источник истины — файл-результат.

## Мини-шаблон

```powershell
# <Что делает и зачем. Откат: ...>
$ErrorActionPreference = 'Continue'
$out = Join-Path $env:TEMP '<имя>-result.txt'
$log = @()
try {
    # правка
    New-ItemProperty -Path 'HKLM:\...' -Name X -Value 1 -PropertyType DWord -Force | Out-Null
    # верификация тем же каналом
    $v = (Get-ItemProperty -Path 'HKLM:\...' -Name X).X
    $log += "X = $v" + $(if ($v -eq 1) { ' — OK' } else { ' — ВНИМАНИЕ, не применилось' })
} catch { $log += "ОШИБКА: $($_.Exception.Message)" }
$log | Set-Content -Path $out -Encoding utf8
$log | ForEach-Object { Write-Host "  $_" }
```
